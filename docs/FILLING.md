## Context

两趟 NTU 实测：普通字段又快又准；一遇到没名字的输入框、看得见点不着的文字、弹层搜索下拉、分步上传，就填错格、把示例当数据、反复找顾问。上一版计划是十几条防守式补丁，用户否了：**太保守、限制太多；要真正新的、能做完的、四两拨千斤的思路**。同时定了：**模型换成 MiniMax M3**（能看图）；**Jev 干活 / 判别，<0.8 交大模型且大模型要真思考；顾问零接手；用人的操作方式；通用，不给单站适配**。

两个事实决定了新方向：

- 刚查到：**MiniMax-M2.7 不支持图片输入**（`image:false`）——前两趟它“截图看页面”其实什么都没看见。**M3：`image:true`、`video:true`、100 万上下文、有 `thinking` 档位、同价**。人靠眼睛认标签，我们之前一直让模型闭着眼睛填表。
- 调研（browser-use / Stagehand / Skyvern / Playwright MCP / Chromium 自动填充 / 视觉方案）：没有能整个拿来用的，也**没有任何开源项目做“长申请表端到端”**。视觉“点坐标”在密集表单上很差（FormFactory <5%），但**视觉“认东西”+ DOM“动手”**的组合没人做透——这就是空档。

## 核心思路（五个巧劲）

### 1. 档案变“答案库”，Jev 给整页“对号入座” —— 让填表从“写作题”变“连线题”
Jev 不会写字，但填表 90% 的值**不用写**，档案里已经有了。把学生档案做成带键的答案库（`family_name`、`given_name`、`passport.number`、`phone.mobile.country_code`、`education[0].gpa` …，大模型读完材料一次写好）。每到一页：把“这一页的所有格子”和“答案库的键名清单”一次发给 Jev，它给每个格子选：**用哪个键 / 不适用（跳过）/ 要大模型想**。一页一次请求，约 1 秒。≥0.8 的直接填（值从答案库原样取，不经任何模型改写，杜绝笔误和编造）；<0.8 的才交大模型。
- Jev 只看到**键名和页面上的字**，看不到学生的值——隐私上比现在更好。
- 这正是 browser-use 官方那个 Jev 项目做不到的：它得另请一个小模型“写字”；我们不需要写。

### 2. 给页面“贴号码牌再拍照”，让 M3 像人一样用眼睛认 —— 标签问题不靠规则
在每个可操作元素上临时叠一个编号小标签（就是我们已有的 `e12` 编号），截图，连同字段清单一起给 M3。它**看图**回答“e27 是 Surname，e28 是 Given Name，e41 旁边灰字是示例不是数据，e52 这个 Change 是选照片的”。看到的和能操作的靠号码牌对上：**认东西用眼睛，动手用 DOM**，不点坐标。标签没关联、表格布局、浮动标签、图标按钮——对人不是问题的，对它也不再是问题。不用为每种写法写一条规则。

### 3. 三个证人对口供 —— 又快又准的来源
每个格子的“它是什么”有三个独立来源：**旁边的字**（几何 / DOM 推断，Chromium 自动填充那套顺序）、**开发者自己起的名字**（`id` / `name` / `autocomplete`：`txtSurname`、`given-name`——我们现在根本没给模型看，这是白送的标签）、**看图**（第 2 条）。三者一致 → 直接填，不用想；不一致 → 这才是该让大模型开 thinking 的地方，证据全摆给它。

### 4. 填完像人一样“校对一遍” —— 错了自己改，不靠顾问发现
每页填完：号码牌截图 + “字段｜当前值”清单 → M3 对着答案库逐项核（“Surname 显示 WEI-JUN，答案库是 HUANG”→ 自己改）。姓名对调、区号配错、示例号码这类“每格读回都一致但整体是错的”，只有这一步抓得住。通过才翻页；翻页被拦，就读页面报的错（`aria-invalid` / 报错文字 / 红框，连字段名一起给）再改。

### 5. 跑一次学一次，接手一次学一次 —— 越用越快，趋近零接手
- **平台经验库**（自动学，不是手写适配）：每个平台每一页的“格子特征 → 答案库的键”、这个控件怎么操作才成（“要先点开再在弹层里打字”“上传要 Upload→选文件→Crop→Save”）、坑（文件名 ≤50 字符）存成数据。**下一个学生上同一个平台：直接照做，几乎不花大模型的轮数**，只做第 4 条的校对。页面变了就自动失效、重新学。顾问一年几十个学生报同样那几十个平台——这是复利。
- **顾问接手 = 示范**：万一顾问动手了（选了个怪日历、传了个怪上传），把他的操作录下来（点了谁、按了什么键），由大模型整理成这个平台这个控件的做法存进经验库。**同一个坑最多接手一次**。

## 每一页的流水线（大模型仍是总指挥，但大部分格子不再花它的轮数）

```
browser_fill_page（新工具，一次调用）
  ① 感知：字段清单（三个来源的名字、示例、必填、当前值）+ 号码牌截图
  ② 经验库有这一页？→ 直接照做，跳到 ⑤
  ③ Jev 对号入座（1 次请求）→ ≥0.8 的立刻填（值取自答案库）
  ④ 剩下的（<0.8、要判断的题、要写的文字）连同截图交回 M3：开 thinking，想清楚，一次 browser_fill_form 补完
  ⑤ 校对：截图 + 清单对答案库 → 自己改 → 通过
  ⑥ 翻页；被拦 → 读报错再改；成功 → 把这一页学进经验库
```
目标：**每页 2–3 次大模型调用**（现在 20–40 次）；已学过的页 0–1 次。

**升级阶梯**（任何一处卡住）：工具自己 → Jev → M3（thinking + 截图）→ 换人的另一种操作方式（键盘：Tab / 打字 / 方向键 / 回车）→ 记进“待顾问清单”继续做别的 → 全部做完一次性问。
**顾问只出现在：** 登录 / 验证码；同意与声明；最终提交、付款、推荐信邀请；答案库里确实没有的信息（最后一起问）。守则里其余四个“去问顾问”的口子全部删掉。

**执行器**（人的操作方式，按行为不按组件库）：真实鼠标键盘；点开 → 只看新冒出来的那一块 → 有搜索框先打字 → 选 → 要“提交证据”（弹层关了、显示变了）；每次点击都挂文件选择框陷阱（出系统选择框就交文件，出页面对话框就照着走下去）；“能点”按行为判定（真实点击监听 / 手型光标 / onclick），“Change”、日历格子一并解决；键盘路径兜底。flatpickr 这类专用接口只当加速器。

## 页面兼容性：DOM 用不了的页面也得能填（用户补充 1）

很多页面连 DOM 都靠不住：canvas / Flutter 画出来的表单、封闭的 shadow DOM、连不上的跨域 iframe、内嵌 PDF 表单、无障碍树是空的。所以感知和动手都做成**三档，自动降级，不是三套代码各写一遍**：

| 档 | 什么时候 | 怎么看 | 怎么动手 | 怎么核对 |
|---|---|---|---|---|
| A 正常 | 无障碍树和 DOM 都有料 | 字段清单 + 号码牌截图 | 按编号，真实鼠标键盘 | 读回值 + 整页校对 |
| B 半瞎 | 有 DOM 但名字 / 角色是空的、可点的东西没角色 | **M3 看号码牌截图认东西**，DOM 只负责定位 | 同 A | 同 A |
| C 全瞎 | 拿不到 DOM（canvas、封闭 shadow、跨域框架连不上、PDF） | **M3 看带网格刻度的截图**，给出“点哪里”（先整页定位大致区域，再放大裁剪图精确定位，两步走，避开密集表单上一步到位不准的问题） | 按坐标的真实鼠标点击 + 键盘（Tab 在这类页面上往往照样能用：Tab 到一格、打字、再截图确认焦点在哪） | **前后截图差异** + M3 看图确认“这一格现在显示的是不是我要的值” |

每个 frame 单独判档（一页里可以主体是 A、某个内嵌框是 C）。判档依据是客观数：可交互节点数、有名字的比例、截图上看得见的控件数和 DOM 里数得到的对不对得上。降到 C 档时工具明说“这一块我看不到结构，只能看图操作”，保留动作 / 同意规则在 C 档改为**对点击位置周围的图上文字**做判断（交 Jev / M3），宁可多问。

## 烦人场景大全 + 盲测基准（用户补充 2、3：开一个子代理并行去做）

**子代理的任务**（与主线同时进行，产出进仓库 `bench/`）：
1. **收集**：把能想到的、真实申请系统里又乱又烦的填表场景全部列出来并分类，**重点是带二级界面的**：点学校名弹出搜索对话框再选（Common App 的高中 / 大学查找、CollegeNET / Slate / Liaison CAS / ApplyWeb / UCAS / 各校自建系统的院校库）、“Add another” 重复段落里再开弹层、级联下拉（国家→省→市→学校）、地址联想、课程 / 成绩逐条录入表格、推荐人子表单、文书富文本 + 字数限制、多文件上传带类型选择、条件分支（选了“是”冒出一整段）、分页向导 + 会话超时、保存后才校验、只读日历、带掩码的证件号、iframe 内嵌支付 / 上传、canvas 签名……每一类写明：长什么样、人怎么操作、机器容易栽在哪。来源：各系统的公开帮助文档 / 演示视频 / 不登录可见的页面；**不登录任何真实账号、不填任何真实数据**。
2. **找现成的真实复杂基准**：上网找公开的、够复杂的表单 / 网页代理评测集（FormFactory、Mind2Web、WebArena / VisualWebArena、WebVoyager、BrowserGym / WorkArena、Online-Mind2Web 等），评估哪一个能拿来跑我们的应用（许可证、能否离线 / 自托管、是否含多页长表单和二级界面），选一套落地；没有合适的就**照第 1 步的分类自建一套“申请系统仿真”**：几个互不相同的多页申请站（不同的前端写法、不同的组件库、至少一个 canvas / 封闭 shadow 的页面），每个站带一份虚构学生材料和一份**标准答案**，用脚本判分（填对率、填错格数、问顾问次数、大模型调用次数、耗时）。
3. **防“提前训练 / 泄题”**（硬要求）：
   - 基准站点、标准答案、场景说明**一律不进**给填表模型看的东西（`resources/AGENTS.workspace.md`、工具描述、答案库键说明、经验库）；放在 `bench/`，运行时不在模型工作区内。
   - 分 **开发集** 和 **封存集**：主线开发只许看开发集；封存集由子代理生成后我不读其页面源码和答案，只看判分结果。封存集每次评测**随机换皮**（字段顺序、标签措辞、id/name、控件种类、页面分法随机化），防止经验库或我自己的规则“背答案”。
   - 评测时经验库默认清空（单独再测一轮“第二个学生”看经验库的增益）。
   - 任何“为了过某一题”而加的站点特征规则，一律不收。

## 分三期，每期都能独立跑通、独立验收

**第一期 · 看得见 + 对号入座 + 校对（本轮做完，回 NTU 验）**
1. 模型：默认 `minimax-cn/MiniMax-M3`，发消息带 `variant: "thinking"`（`src/main/index.ts` `sendPrompt`；`promptAsync` 已支持 `variant`）；界面显示思考档位；不能看图的模型在选择器里标出来。

3. 感知：`snapshot.ts` 给每个字段加三个来源的名字 + 开发者命名 + `示例：…（不是数据）`+ 必填 / 标红 / 报错；新增 `labels.ts`、`clickable.ts`（行为判定的可点节点）。
4. 号码牌截图：`controller.ts` 临时叠编号层 → 截图 → 撤掉；`browser_screenshot` 增加 `marks: true`。
5. `browser_fill_page`：新增 `src/main/browser/autofill.ts`（Jev 对号入座的出题与判定，纯函数可单测）+ `controller.ts` 编排 + `mcp.ts` 注册；复用 `match.ts` 的 `pickOption`、`jev.ts` 的 `askJev`。
6. `browser_review`：清单 + 号码牌截图；`clickCore` / `fillForm` 结果最前面写“变了什么、哪几项报错（带名字）”。
7. 执行器：弹层差分 + 提交证据 + 键盘兜底（重写 `chooseCustom`）；上传改成陷阱 + 对话框续走，英文短文件名；先验证 `Page.setInterceptFileChooserDialog` 在内嵌浏览器里可用。

**第二期 · 平台经验库**：`src/main/browser/recipes.ts`，存在 `<应用数据>/recipes/<域名>/<页面指纹>.json`（格子特征→键、控件做法、坑）；命中即照做 + 校对；失配自动失效重学。

**第三期 · 接手即示范**：页面内录制顾问操作（捕获阶段监听 click / input / keydown + 元素特征），M3 整理成做法写入经验库。

## 怎么验证（通用，不复现某一个站）

1. **控件动物园** `fixtures/zoo.html`：标签 6 种写法 × 下拉 6 种 × 日期 5 种 × 上传 4 种 × 报错 3 种；`bun run smoke` 全过，`NEO_JEV=off` 也全过（没有 Jev 时对号入座整页交给 M3，功能不缺只是慢）。
2. **对号入座基准** `bun run smoke:map`（真 Jev，不碰网页）：拿 NTU 三页的真实字段清单 + 动物园，量“≥0.8 且选对”的比例、“≥0.8 却选错”必须为 0；先做这个小试验，数字不行就调出题方式，再往下做。
3. **公开网页回归** `bun run smoke:sites`（不登录不填真数据）：组件库官方示例页 + 几个申请平台不登录可见的页面；量字段命名率、可点覆盖率（目标 ≥95%）。
4. `typecheck` + `bun test src` + `smoke:e2e`（M3 thinking + 真 Jev）：记录每页大模型调用次数、总耗时、**问顾问次数（练习表目标 0）**。
5. **回 NTU 第三趟**：改掉草稿里三处错，7 个标签走完存草稿不提交；顾问只应在登录、隐私声明、保留动作、确实缺的信息（最后一次）出现。
6. 第二期验收：同一平台换一个学生再跑，大模型调用次数应掉到每页 0–1 次。再换两个不同体系的真实平台（用户挑）。
