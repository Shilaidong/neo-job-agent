# 浏览器层：谁决定什么、坑在哪、什么叫“跑通”

> 2026-09-19 重新想过一遍后写的。改浏览器工具（`src/main/browser/`）之前先读这一篇。
> 进度在 [ROADMAP.md](ROADMAP.md) 的 M6 / M7；这里讲的是**为什么这么做**和**每种坑打算怎么对付**。
> （2026-10-11 校注：M4/M4.9 都已完成，文中「M4 之后」字样读作「现状」即可；Jev 的接法自 2026-10-08 起改由设置界面的 Jev 行决定，见 §5。）

## 0. 通用性原则（2026-09-19 用户定调）

> “不能只给一个网站做适配。我们要的是通用的申请。”

浏览器层**不认网站、不认组件库，只认行为和几何**：它旁边写着什么、它能不能点、点了之后出来了什么。三件事必须对任何网页成立：

- **看**：模型拿到的文字版 = 人眼看到的页面（每个字段有人认得的名字，能点的都有编号，必填 / 标红 / 示例文字照实标出）。
- **做**：工具的动作 = 人的动作（真实点击、看出来什么再处理；不走页面自己都不认的捷径）。
- **核**：不只核对“填进去的 = 我给的”，还要让“填对了格”看得出来（结果带字段名，翻页前整页回看）。

组件库的专用接口（比如 flatpickr 的 setDate）只能是**加速器**：有就快一点，没有也必须走得通。每一条修法都要能回答：“换一个没见过的网站，它凭什么还管用？” 验收同理——按控件类别建“动物园”，拿一组公开网页量命名率和可点覆盖率，而不是复现某一个站。计划在 ROADMAP 的 M4.9。

## 1. 三个角色

```
大模型（OpenCode 里那个）      决定“填什么”：读材料、写档案、每个字段该填什么值、和顾问说话
        │  一次工具调用 = 一段表单（十几个字段）
        ▼
浏览器工具（我们的代码，CDP）   负责“动手”：点、敲字、选、传文件、读回实际值        ← 毫秒级
        │  动手过程中遇到“选哪个”的小问题
        ▼
Jev（小模型，只会做选择题）     负责“选哪个”：下拉里哪一项 = “中国”、这个弹层该点哪个按钮、
                               日期该用哪种格式、这个按钮是不是“最终提交”             ← 0.5–1 秒
```

**为什么要 Jev。** 我们的工具本身是毫秒级的，慢在大模型的轮数：下拉里没有字面一样的选项 → 工具把候选退回去 → 大模型再想一轮（几秒到十几秒）→ 再调一次工具。一页表单里这种“小问题”有十几个。Jev 0.6 秒答一道选择题，工具在自己内部就把问题解决了，大模型一轮能填完一段。

**Jev 不能做什么。** 它**写不出一个字**：只能从给定选项里选一个（附每个选项的概率）、打分、或回答是/否。所以“这个字段该填什么”永远是大模型的事；Jev 只管“怎么把这个值弄进页面”过程中的选择题。它也看不了截图。

实测数据（2026-09-19，Vercel AI Gateway，`typesafe-ai/jev`）：

| 测了什么 | 结果 |
|---|---|
| 延迟 | 小请求中位 0.64 秒（0.43–1.6）；1.4 万 token 的大页面 0.78 秒 |
| 下拉选项匹配（16 例，中文值 → 英文选项） | 对 15；错的那例把握只有 0.67（其余中位 1.00）——“中国本科”算 Honours 还是 Ordinary，本来就该问人 |
| 三类保留动作识别（36 例，带一句页面上下文） | Jev 对 34、**该拦没拦 0**；现有关键词规则对 22、该拦没拦 10 |
| 一次请求问 16 道题 | 0.86 秒 —— **一次工具调用里的所有选择题合成一次请求** |
| 免费档 | **约每 5 分钟只放行 5 次**，其余 429。只够试，不够用 |

顺带结论：GitHub 上的 `wy-coliney/jev-browser-use` **不能拿来用**——它只是 OpenAI Codex 浏览器上的一层胶水，不支持填字、下拉、iframe、上传；页面上有倒计时就一步不走、重名按钮（Yes/No、Add）一律不点、页面超过 24000 字符直接抛异常。我们借的是 Jev 这个模型，不是那个仓库。

## 2. 三条规矩

**① 0.8 线。** Jev 选中项的概率 ≥ 0.8，工具直接照做，并在结果里说清楚（“按‘中国’选了 ‘China, People's Republic of’”）。低于 0.8，工具**不动手**，把候选项和 Jev 的倾向一起退给大模型（“相近的选项：A | B | C；小模型倾向 B，把握 0.67”）。大模型懂得多、还能查资料，由它定；它也拿不准就问顾问。

**② Jev 是加速器，不是依赖。** 没配密钥、超时（3 秒）、被限流、服务挂了——工具一律**立刻退回没有 Jev 时的行为**（把候选退给大模型），不等、不重试、不报错给顾问。日志里记一行 `mod=jev`。有没有 Jev，所有功能都得能跑通，只是快慢不同。

**③ “跑通”标准与放弃。** 现在只有一个用户，目标是**一次跑通**，不是覆盖所有控件。

- 工具内部：同一个字段最多换 2–3 种办法（比如日期：直接打字 → 逐字慢打 → 操作日历），都不行就如实返回“试了什么、页面现在什么样”。
- 大模型：同一个字段自己再试不超过 3 次，还不行就**记下来、跳过、继续填别的**，最后一起告诉顾问“这几项请你手动填”。写进一页纸守则里的一句话，不做成闸门。
- 顾问手动填完说一声，模型重新看页面接着做（现在就支持：以页面实际样子为准）。
- 不为没遇到过的控件提前写代码。真实平台上撞到了，先加进练习表 `fixtures/form.html` 复现，再修。

**给 Jev 的东西越少越好。** 只发这道题需要的片段（字段名、想要的值、选项列表、弹层上的文字），**不发整页快照、不发学生档案**。一是省钱省时间，二是页面文字多经一家第三方（Vercel 标注不留存、不训练，但少发总没错）。

### 自动登录（2026-10-09 拍板 B「全程不经模型」→ 2026-10-12 改为「递到眼前的凭据交给模型来认」）

客户反馈想省掉“AI 到登录页停一下、顾问敲密码”这一步。B 的方案起初定成密码**全程不经模型**；资料扫描 + 本机缓存这条主干就是这么跑下来的，照旧。2026-10-12 用户改口：「软件侧用纯 regex 解析出账号和密码直接进钥匙串 这个我觉得不行，直接用模型来处理吧」——顾问**主动递**的凭据（贴进「平台登录」框、或打进对话）从此不走解析的路，原样交给模型去认、原样传回登录工具。明的账：这类密码会进模型上下文、会话日志和 task.json——现在填表模型都在本地（2026-10-10 口径），哪天给任务选了云端模型，它随任务内容一起出网。

- **存（正源=资料，2026-10-10 改）**：调 `browser_login` 时这台机器没存过密码，主进程先拿 `material-creds.ts` 扫学生资料目录（`materials_text/` 全部 .md/.txt + `student.json`/`student_profile.json`）：在“密码/password/pwd：…”那行旁边（往上看 6 行）找得到这个站名的那条就认定这条记录，顺手缓存进 `platform-passwords`——**两种例外**：① 这条记录长得像随手记的散句（loose）就用它、**不进缓存**，下次还是现扫现用，免得一句误读被钉死成“这台机器的正源”（2026-10-11 login-creds 纯函数钉死，P1-2）；② 扫描没找到值、但该站在资料里被 `redactSecrets` 打码隐去过、缓存里也没有——**throw 交顾问手动补录，绝不拿打码串去试**（P1-1）。资料里写清了几站就归几站，**两处都指着这个站点就 throw 交顾问、绝不猜**；资料里没有这个站，才回落到手动补录的那条（有缓存时哪怕缓存的那次登录值打过码，也照用缓存——补录过的密码是正源，压过一条打码记录，这个优先序也有单测钉着）。任务表单勾【允许自动登录】，旁边是**「平台登录」整段粘贴框**（2026-10-12 替代旧“敲一次密码直进钥匙串”的补录框；单建和导入选校清单两页都有——清单页贴一次，随这批创建的每个任务进各自开场白，模型只在贴到的那一站用）：顾问整段贴，一行也好一段备忘也好，软件不拆它，原样进 `TaskInput`/task.json、随启动信息交模型自己认。**第四个载入口（2026-10-14 学生「编辑」）**：账号备忘按学生存——edit 页整段替换，落 `student-memos` 加密存储（同样是 `auth:` 档、躺在工作区之外，材料扫描天然够不着它），开每个任务时以「平台登录」标题随开场白进对话，照旧由模型自己认。它和逐任务那段并存不互斥：那段只对贴到的这一站，备忘管这个学生所有站，两处都有的任务两段都会带上。一个如实的口子：`--smoke-tasks` 的无窗启动态里，第一次 keychain 调用会挂在一个没人能点的同意弹窗上，所以这条腿在 smoke 里走 in-memory 缝（`setMemoStoreForTests`）；加密本体与 `platform-passwords` 同一套机制、同一台机器上 browser smoke 钉着，真应用里顾问点一次「总是允许」就够了。钥匙串档位不变：`auth:` IPC 走 OS 加密存储（该前缀的 IPC 失败日志整包打码），文件躺在工作区之外；`clearPlatformAccount` 顺手删密码。**递参那条正源优先**：模型带回来的 `username`/`password` 就地用、登成顺手缓存，往后这一站回到零参数；扫描那条**资料有记录时以资料为准**：顾问改了资料里的密码，下次登录就用新的。扫描本身照旧在软件侧做——批量导入选校清单那页也放了同一个开关，一路传进每个任务。
- **用**：`browser_login` 从此两种调法——零参数，controller 经注入的 `loginCredentials()` 拿凭据（资料→加密存储，老路子）；或把顾问刚给的账号密码原样当 `username`/`password` 参数带回来。拿到凭据后照旧：按“密码框前的文本框当账号”填账号、`Input.insertText` 打密码、点登录按钮/回车。不回显的纪律：密码框**读回只取长度**（`fields.ts` 取证本来就不读密码框的值，这条照抄）、返回文本只有页面快照；日志由 sanitize 兜底，args 里嵌套的 `password` 键照样打码。口径变了的那一笔：**带进来的参数密码会进模型上下文与会话日志**——这是拍板明说的代价，换来的是「资料里没记的站，顾问贴一次就能登」；【允许自动登录】关着或没 `applicationUrl` 时，带参的登录同样不开——始终有这一道闸。**拒了就忘**（2026-10-12 评审 P2）：这站明确说密码不对时，刚收到、刚缓存的那对会被从本机清掉——错的密码不会留在钥匙串里让下一次零参数调用再试一轮。
- **堵**：`fill`/`type` 从此拒碰密码框（2026-10-09 前的现实：模型往密码框打字，值会明文出现在 mcp 日志的 args 和回显里——sanitize 只按 key 名打码，`value`/`text` 这种键名根本不命中）。`browser_fill_page` 走的也是 `fill`，一处守卫三处生效。2026-10-12 换了口径，这条守卫反而更关键了：密码能进模型的口，唯一的收口就是 `browser_login`——想登别的站，拿参数去敲它的门，别绕路填框。
- **停**：验证码/2FA（快照扫 “verification code / 验证码” 类字样）、密码不对、没凭据、这页没密码框——全部停下交顾问，与登录归人的旧口径同一形状；没凭据那条的回话会补一句「顾问刚给了这站的账号密码就带参再调一次」，除此以外不教模型任何打密码的路。ego lite 页同一套原语（`bindHost` 换绑不改工具），没做额外分支。
- 代码：`accounts.ts`（secret store + get/save/clear）、`material-creds.ts`（资料扫描纯函数 + 目录游走，单测钉命中/没有/模糊）、`login-creds.ts`（扫描之后怎么办的纯函数：缓存写不写、loose 跳过、打码 throw——2026-10-11 实测员留洞后从 index.ts 的闭包里拆出来，9 例；2026-10-12 加 `resolveCredentials`：递参优先、登成顺手缓存，钉到 13 例）、`errors.ts`（`BrowserError` 叶子模块：只 throw 不碰页面的调用方 import 它，免得 Electron 顺着 controller 被拖进 bun-test 的模块图；controller 原样再导出，老 import 不动）、`controller.ts`（`login(explicit?)` + fill/type 守卫 + `setLoginCredentialsForTests` 缝）、`mcp.ts`（`browser_login` 挂可选 `username`/`password` 参数）、`index.ts`（`loginCredentials` 注入：扫描 + `resolveCredentials` + `auth:` IPC，带参时不过扫描）、`NewTask.tsx`（开关两模式共有 + 「平台登录」整段粘贴框）、`start-prompt.ts`（开关开场白 + 「平台登录」一段原样上首条消息）、`tasks/student-memo.ts`（学生「编辑」页的账号备忘 secret store + get/set）、`tasks/reimport.ts`（同一页的选校清单三分 diff，见 ROADMAP 2026-10-14）。`web.ts` 是同一时期的另一条腿：`browser_search` / `browser_open` 的后台隐藏页（不占任务页，归 `mod=web` 日志）。smoke：`fixtures/login.html` 三条路（过 / 要码 / 密码错）+ 密码不落日志断言 + 「只有材料里有密码、没缓存」一条路 + 「递参登录」一条路（2026-10-12：带账号密码登成、日志无明文、缓存已在——下一回零参数照用）。

## 4. 工具的样子（M4 之后）

大模型常用的只剩这几个；其余（`click`、`fill`、`press_key`、`hover`……）都留着，给特殊情况用。**没有“执行页面脚本”的工具**：第一次真实实测里它被用来绕开日期核对、关掉网站自己的必填校验、伪造上传文件（REALRUN-NTU.md B1）。模型写出来的东西永远不变成脚本或选择器；坐标只留给页面上**没有结构可编号**的区域（见下 `browser_click_at`）。

| 工具 | 做什么 |
|---|---|
| `browser_snapshot` | 看页面 |
| `browser_fill_form` | **主力。** 一次交一段：`[{ref, value}]`，每个字段可以是文本、下拉、自绘下拉、单选组、复选、日期。工具按控件类型自己选办法，逐个读回。某个字段失败不影响后面的，只有弹出对话框才停。结果逐条列出：✓ 填上了 / ⚠ 读回不一致 / ✗ 没填上（没把握时附候选）；最后附一份填完后的快照，并点名哪个选择引出了新字段。不替模型点普通按钮 |
| `browser_choose` | 单个选择类控件：`ref` + 想要的值 |
| `browser_do` | 把一段只需要“点”的路交给 Jev 去走（找到申请入口、切标签、展开各段）：一步零点几秒，不打字，拿不准就停；每一下照样过保留动作。详见 REALRUN-NTU.md §3 |
| `browser_click` | 翻页、保存、Add another…… |
| `browser_fill_page` | **每页第一步。** 这一页的空格子和答案库对号入座（Jev，一页装不下一次请求时自动分批并行），有把握的直接填，其余连证据和带编号的截图交回（docs/FILLING.md） |
| `browser_review` | 翻页前核对整页：字段名｜当前值｜必填｜页面标的错 + 带编号的截图 |
| `browser_upload` | 传文件：像人一样点开入口，接住文件选择框或跟进站点自己的上传界面 |
| `browser_screenshot` | `marks` 贴编号；`grid` 画坐标刻度；`region` 只截一块并放大 |
| `browser_search` / `browser_open` | 上网查东西、读官网页。**在后台的一个隐藏页里跑**（同一个浏览器配置，登录态通用），**绝不动顾问正在填的那一页**。结果链接会跟到它真正指向的地址（搜索引擎都套一层自己的跳转）。OpenCode 自带的 `webfetch` 已经从模型手里拿掉（**在每条消息上传 `tools: { webfetch: false }`；写在注入配置里的同名键实测完全不起作用**，模型照样调得动——实测确认过两次）——它抓搜索结果页时约 20 次里被拒 15 次；它自带的 `websearch` 我们用不了（只对它自家 provider 或付费 Exa / Parallel 开放） |
| `browser_click_at` | **C 档兜底**：canvas 画出来的表单、内嵌文档这类没有结构的区域，按坐标点；位置上有编号元素就拒绝；保留动作同时看模型说的 `what` 和该位置的字；返回点击前后画面哪里变了 + 新截图 |

**自绘下拉怎么选（按行为，不按组件库）：** 点开 → 只看**新冒出来的那一块**（网站声明了 option 就用声明的，没声明就取新出现的、并排的那一组行）→ 控件本身能打字、或弹层里有搜索框，就先打字（搜不到再清空看全量）→ 列表一次只画几行就像人一样滚 → 选 → **要证据**：弹层收起了，或控件显示的内容变了；没有证据就用键盘再来一次（打字 + ↓ + Enter）；还没有就如实说“不能算选上了”，不报成功。

### 模型看不了图时（纯文字模型，sees=false）

浏览器架构是**文字优先**的：工具返回以字段清单、名字、读回值、报错文字为主，截图本来就是证据不是承重墙——所以纯文字模型**跑得通**。机制在 opencode 侧：模型条目标 `modalities.input=["text"]` + `attachment:false`，拼请求时图片 part 整套丢弃，服务器端连「这不是多模态模型」的 400 都碰不到（2026-10-11 在 vLLM 前架录制代理实测确认：e2e 全程 11 次请求 `images=false`，任务照常填完）。工具照旧附截图，只是模型收不到——**不用改任何一行浏览器代码**。

失明的部分按 FILLING.md 的三档数：A 档（DOM + 无障碍树）完好；B 档「看号码牌截图认东西」降级成纯靠名字/顺序猜，读回核对仍有效；C 档「看图点坐标」整个不能用，`browser_click_at` 没有模型给得出坐标。**「用 read 打开原图核对」这条安全网也失灵**——材料本来就先 OCR 成文字，正常路径不受影响，只是「扫描件可疑时让人看一眼原件」这个兜底没了。卡住的出口不变：升级阶梯最后一步是记进待顾问清单交人，顾问本来就在看左栏页面。

## 5. Jev 的接法

- 代码在 `src/main/jev.ts`，只有一个入口：`askJev(state, questions, workspace?) → answers | undefined`。`undefined` = 不可用，调用方走老路。不含 Electron 的部分在 `jev-core.ts`（单测测的是它）。
- **路由（2026-10-08 起以设置界面为准）**，`jev.ts` 里从上往下第一个命中生效：
  1. `setJevBackendForTests()` 装的后端（自检）；
  2. `NEO_JEV=off`（没有）/ `NEO_JEV=fake`（内置假 Jev）；
  3. `NEO_JEV_BASE_URL`——env 门，设了就压过设置界面，开发和自检的明确通道（局域网集群也走这里，约 0.3 秒，模型名可 `NEO_JEV_MODEL` 覆盖）；
  4. **设置界面的 Jev 行**（`jev-servers.ts`，2026-10-08 交付）：选中的那条经 `typesafeBackend` 答话——OpenAI 兼容接口 + 行里带的 Key，行选「关闭」就是没有；
  5. `NEO_TYPESAFE_KEY` 直连 TypeSafe 官方云；
  6. `NEO_JEV_KEY` 退到 Vercel AI Gateway 兜底。
  前三档都是 env/测试通道，正常装机只有第 4 档。
- **密钥**：走设置界面这条路，Jev 行（含云 Key）存 `userData/jev-servers.json`——**明文**，和 `model-servers.json` 一个待遇（2026-10-08 用户拍板不走钥匙串；「明文要不要上锁」还挂在待议）。云 TypeSafe Key 本身在代码的 seed 行里**随安装包分发**（2026-10-10 用户拍板「这玩意不值钱，随包带着」——它推翻了旧「不进 dmg」的规矩；轮换那件事挂在 ROADMAP 待议）。env 里那两把只作开发覆盖。**Key 不进日志、不进发给 Jev 的内容、不传给 OpenCode 子进程**（它的命令行工具会继承环境变量）。
- TypeSafe 直连这条路：`POST api.typesafe.ai/v1/systemone`，实测热连接约 0.3 秒。Vercel 那条：模型 `typesafe-ai/jev`，用 AI SDK（`ai` ≥ 7 的 `experimental_evaluate`；这类模型不走 OpenAI 兼容接口，所以 OpenCode 调不了它），约 0.7 秒——纯 JS 依赖，不违反「不引入原生模块」，现在只剩兜底身份，早年「免费档每 5 分钟 5 次」的限流提醒作废。
- 超时 3 秒（`NEO_JEV_TIMEOUT_MS` 可调）；被限流或连续失败 3 次后，60 秒内不再尝试（免费档限流时别每个字段都白等一次）。
- 同一道题（同样的选项 + 同样的值）结果缓存在学生工作区 `.cache/jev.json`——同一个学生申请十所学校，“中国”只用问一次。
- 每次调用一行日志：问了几道题、耗时、每题选了什么、把握多少、是否命中缓存。
- 自检不依赖网络：`NEO_JEV=fake` 用内置的假 Jev（按字面相似度选），`NEO_JEV=off` 完全关闭。需要真判断力的自检（“中国”→“China, People's Republic of”）用 `setJevBackendForTests()` 装一个照剧本回答的后端。真 Jev 只在 `bun run smoke:jev`（1 次调用）和 `smoke:e2e` 里出现。

## 6. 怎么算 M4 做完

1. 练习表 `fixtures/form.html` 加上这些坑：中文值对英文选项的国家下拉、可搜索的自绘下拉、年月日三下拉、`MM/DD/YYYY` 文本日期、只读日历、挡住表单的 cookie 弹层、“会话即将过期”弹层、换了说法的提交按钮、回车即提交的表单。
2. `bun run smoke`（假 Jev）全过；关掉 Jev（`NEO_JEV=off`）也全过。
3. `smoke:e2e`（真大模型 + 真 Jev）：**一次跑通**——练习表填完并保存，三类保留按钮没碰，搞不定的字段被列出来交给顾问而不是卡住。记录大模型轮数和总耗时，和接入前（44–53 秒）对比写进 ROADMAP。
4. 真实平台至少跑一个（登录由用户自己来），撞到的新坑补进本文的清单。
